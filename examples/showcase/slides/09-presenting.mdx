<Col>

```mdx
<Notes>
Open it with S. [click] Notes follow…
</Notes>
```

</How>

</Col>
</Cols>

<Notes>
Press S to open the presenter window; it stays in step with this one through the browser, and with the room when there is one.
[click] The notes are split at each `[click]` marker, and the presenter view lights the part for the current step — this sentence is lit at step two.
[click] Pacing: `defaultTiming: 45` in the headmatter gives every slide forty-five seconds, and this one asks for ninety. The timer tells you whether you are ahead or behind.
[click] L cycles three layouts: notes on the right, notes on the left, and the next slide large.
</Notes>

## Run the talk from one window

<Cols cols="1fr 1fr" gap="3rem" align="start">
<Col>

<Clicks>

- A **stopwatch or a countdown** — `timer: countdown`, `duration: 30min` — that pauses, resets, fills a progress bar and goes red in overtime, with the pacing badge beside it
- **Notes you can edit** in the presenter, on `/overview` and on `/notes-edit` under `kadal-deck dev`: saved into deck.mdx, no reload
- **Markers you can click**: each `[click]` in the notes jumps to its step
- **`/overview`**: every slide with a step slider and its notes

</Clicks>

</Col>
<Col>

<How>

```mdx
---
timer: countdown
duration: 30min
---

<Notes>
Open on the problem. [click] The chart.
[click:4] Skip to the ask.
</Notes>
```

</How>

</Col>
</Cols>

<Notes>
Everything a talk needs, in the presenter view.
[click] The top bar holds the timer: click the time to pause it, the arrow to reset, the chevron to switch between stopwatch and countdown or change the length for this talk.
[click] Under `kadal-deck dev` every notes panel has an Edit button. Cmd or Ctrl+S, or clicking away, writes just this slide's notes back into the file, and the views update in place.
[click] These numbered circles are buttons: press one and the deck jumps to that step.
[click] And /overview lists every slide with a slider through its steps, the notes beside each one.
</Notes>

## Shortcuts, a right-click menu, and display settings

<Cols cols="1fr 1fr" gap="3rem" align="start">
<Col>

- **Right-click** a slide (or <Kbd>⇧</Kbd> <Kbd>F10</Kbd>): move, overview, presenter, notes, full screen, dark, pen, laser, export — and this deck's own *Back to the start*
- <Kbd>,</Kbd> opens the **display settings**: brightness, contrast, saturation, sepia, hue, invert, for a projector that needs it
- <Kbd>E</Kbd> is this deck's own shortcut — <Kbd>?</Kbd> lists it with the rest

</Col>
<Col>

<How>

```tsx
<Deck
  shortcuts={[{ keys: ["KeyE"],
    command: "view.toast",
    params: { message: "Hello" },
    description: "Say hello" }]}
  contextMenu={(items) => [...items,
    { id: "start", label: "Back to the start",
      command: "nav.first" }]}
/>
```

</How>

</Col>
</Cols>

<Notes>
Three things for the room you are in. The context menu runs the same commands as the keyboard, so it offers only what works in this window. Display settings are kept per deck in this browser and reach every window of it — tune the projector from the presenter view. And shortcuts: an array adds to the defaults, a function gets them and returns the whole list.
</Notes>

## When a slide arrives, and leaves

<Cols cols="1.2fr 1fr" gap="3rem" align="center">
<Col>

<EnterCounter />

<p className="sc-small">Go down and back up: one enter per arrival, one leave per departure. The presenter's next-slide box, the overview and print never count.</p>

</Col>
<Col>

<How>

```tsx
useSlideEnter((e) => {
  start(e.direction);
  return () => stop();
});
useSlideLeave(() => save());
```

</How>

</Col>
</Cols>

<Notes>
Slides stay mounted while they are near, so mount and unmount are not "shown". `useSlideEnter` and `useSlideLeave` are: an enter can return a cleanup that runs on leave. `onSlideEnter` and `onSlideLeave` are the same hooks under other names.
</Notes>

## Drawings that stay

<Cols cols="1fr 1fr" gap="3rem" align="center">
<Col>

- With `drawings: { persist: "files" }`, what you pin on `kadal-deck dev` is written to `drawings/<slide>.svg`

- `perClick: true` ties each stroke to the click it was drawn on

</Col>
<Col>

<div className="sc-flow">

</Col>

<Notes>

</Notes>

## Your phone as the clicker

<Cols cols="1fr 1fr" gap="3rem" align="start">
<Col>

<Clicks>

- In the presenter view, **Phone remote** shows a QR code; the phone that scans it becomes the remote
- Next and back, blackout, the slide list, the notes for this step, the timer with buzzes at the minutes you choose
- A live copy of the slide: touch it to aim the laser, draw on it, or tap to zoom; hold the pointer button and move the phone to point
- One phone at a time: the code changes every 30 seconds, and the newest phone to scan takes over

</Clicks>

</Col>
<Col>

<How label="where the phone pairs">

```sh
# a published deck: through its room, nothing to run
# writing it: the dev server relays it
kadal-deck dev --host --https    # motion sensors need https
# a build on a static host
kadal-deck relay --tunnel        # prints a wss:// address
```

```ts
// deck.config.ts, for the static host
remote: { relay: "wss://…" }
```

</How>

</Col>
</Cols>

<Notes>
The phone remote.
[click] Open the presenter view and press Phone remote: a QR code appears, and the phone that scans it runs the deck.
[click] Everything a clicker does, and the notes and timer in your hand.
[click] The slide on the phone is live: a finger on it is the laser, the pen, or a zoom; the air pointer uses the phone's motion sensors.
[click] Pairing is one phone at a time, with a code that keeps changing, so a photo of the screen is soon worthless. Published decks pair through the room; on your own machine the dev server or `kadal-deck relay` carries it.
</Notes>

## Every action is a command

<Cols cols="1fr 1fr" gap="3rem" align="start">
<Col>

Keys, buttons, the phone remote and AI agents all run the same registry, so each does exactly what the others do. Try them:

<div className="sc-run-row">
  <RunCommand command="view.toast" params={{ message: "Hello from a command" }}>say hello</RunCommand>
  <RunCommand command="view.help">the key sheet</RunCommand>
  <RunCommand command="view.colorScheme">dark or light</RunCommand>
</div>

</Col>
<Col>

<How>

```ts
const deck = window.__deck;
deck.commands.list();               // ids, descriptions, parameters
await deck.commands.run("nav.next");
await deck.commands.run("present.laserAt", { x: 0.5, y: 0.4 });
```

```sh
kadal-deck mcp   # the same for an agent, over MCP
```

</How>

</Col>
</Cols>

<Notes>
The command registry. Everything a person can do to a running deck has an id, a description and typed parameters: the keyboard runs through it, and so do the phone remote and the MCP server an agent talks to. The buttons on the left run three of them.
</Notes>

<Cols n={2} gap="2rem" align="start">

## This slide has no number

<Cols n={2} gap="2rem" align="start">
<Col>

`visibility: uncounted` shows it but leaves it out of the count: the number in the corner is gone, and the next slide carries on from the one before.

`title:` names it in search and the outline, `routeAlias:` is a second address (<Link to="no-number">#/no-number</Link>), and `preload: false` loads its module only when it is shown.

</Col>
<Col>

<How>

```yaml
---
visibility: uncounted
title: A slide without a number
routeAlias: no-number
preload: false
---
```

</How>

</Col>
</Cols>

<Notes>
More per-slide options. An uncounted slide is shown but not numbered — an aside, a backup slide. Its title for search comes from frontmatter rather than its heading, it answers to a second address, and it is not loaded ahead of time.
</Notes>

## Export

<Cols cols="1fr 1fr" gap="3rem" align="start">
<Col>

<How label="in the deck's folder">

```sh
kadal-deck export                  # PDF
kadal-deck export --png --pptx     # + a PNG per page, PowerPoint
kadal-deck export --format pptx-editable,md
kadal-deck export --range 1,4-9 --dark --no-with-clicks
```

</How>

<p className="sc-small">No terminal? <a href="export">/export</a> does PDF, PNGs, PowerPoint and Markdown in the browser, with a preview.</p>

</Col>
<Col>

A headless browser prints `?print-pdf`: each PDF page is a picture of the slide with its text over it, so glass, glows and gradients look the same in every viewer and the words can still be searched. The PowerPoint is a picture per slide with your notes attached, so it looks exactly like the web; `pptx-editable` rebuilds the slides as real text boxes, lists and shapes instead.

<Callout kind="tip">Embedded pages are photographed first, so paper gets a picture where the page was.</Callout>

</Col>
</Cols>

<Notes>
Export drives a headless Chromium over the print view. PDF comes from the browser's own printer, with bookmarks from the slide titles; PNGs are a screenshot of each page; the PPTX wraps those pictures one per slide with the speaker notes attached; Markdown puts each picture above its notes. Every deck also has /export, the same in the browser with no install.
</Notes>
