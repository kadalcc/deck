## A renderer is two functions

<Cols n={2} gap="2rem" align="start">
<Col>

<How label="main.tsx — register by name, fetched on first use">

```tsx
registerLazyRenderer("vue", () =>
  import("@kadal/deck-vue").then((m) => m.vueRenderer),
);
```

</How>

<How label="components.tsx — an island">

```tsx
<Island
  framework="vue"
  load={() => import("./vue-ticker.ts")}
  client="slide"
  props={{ step: useClickIndex() }}
/>
```

</How>

</Col>
<Col>

<How label="a renderer, for a framework the engine never heard of">

```ts
export const myRenderer: DeckRenderer = {
  name: "mine",
  mount(host, component, props) {
    const app = create(component, props);
    app.attach(host);
    return {
      update: (next) => app.set(next),
      destroy: () => app.detach(),
    };
  },
};
```

</How>

</Col>
</Cols>

<Notes>
The whole extension point. A renderer puts a component into an element and takes it out again, with an optional update. `client="slide"` is the deck's own hydration rule: alive while the slide is up, gone when it is left — neighbours are mounted for smooth transitions, so hydrating all of them would be how a phone runs out of memory.
</Notes>
