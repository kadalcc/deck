## One file is the whole deck

<Cols cols="1.05fr 1fr" gap="2.5rem" align="start">
<Col>

```mdx {1-4|5-6|7-9|10-12|13-14|15-17} [deck.mdx]
---
title: My talk
theme: minimal
---
# Hello, room
<Notes>Say hi. [click] Then this.</Notes>
---
layout: two-cols
---
## Left
::right::
And right.
----
## Beneath, one ↓ away
---
src: ./chapters/more.mdx
---
```

</Col>
<Col>

<div className="sc-steps">
<Click at={0}>**Headmatter** configures the deck — any option, which `deck.config.ts` can override.</Click>
<Click at={1}>**`---`** starts a slide. **`<Notes>`** are yours; each `[click]` lines them up with a step.</Click>
<Click at={2}>**Frontmatter** right after a separator styles one slide: its layout, background, transition.</Click>
<Click at={3}>**`::right::`** fills a layout's named slot.</Click>
<Click at={4}>**`----`** puts a slide *beneath* the last: <Kbd>↓</Kbd> to read it, <Kbd>→</Kbd> to skip it.</Click>
<Click at={5}>**`src:`** pulls in another file. Each chapter of this tour is one.</Click>
</div>

</Col>
</Cols>

<Notes>
Six pieces of syntax, and that is the format. The headmatter at the top of the file configures the deck.
[click] Three dashes start a slide; the notes you are reading now are a `<Notes>` block, and every `[click]` in them is a step marker — the presenter view highlights the part you are on.
[click] A YAML block right after a separator is that slide's frontmatter.
[click] Named slots split a slide for its layout: `::right::` is the second column of `two-cols`.
[click] Four dashes make a vertical slide — a detail the audience can skip. Press down on any slide in this tour that has something beneath it.
[click] And `src:` includes another file, which is how this tour is organised: one file per chapter.
</Notes>

## Two columns, one slot marker

This slide is `layout: two-cols`. Everything above the marker lands in the left column — the default slot.

<Callout kind="note" title="Any layout can take slots">A line `::name::` starts the slot called *name*; a layout places each slot by its `data-slot`.</Callout>

::right::

<How>

```mdx
---
layout: two-cols
---
## Two columns, one slot marker

This slide is `layout: two-cols`…

::right::

<How> … this panel … </How>
```

</How>

<Notes>
A layout with two named regions. The text before `::right::` is the default slot, the left column; after it, the right. Slots are a compile-time split: each becomes a `div` with `data-slot`, so a layout's stylesheet can place it.
</Notes>

## A layout of your own

`layout: spotlight` is not built in. The deck registers it — one React component under the name `layout:spotlight` — and any slide can ask for it. Frontmatter reaches the layout as a prop: the band on the left reads `eyebrow:`.

<How>

```tsx [src/components.tsx]
function SpotlightLayout({ frontmatter, children }: LayoutProps) {
  return (
    <div className="deck-layout deck-layout-spotlight">
      <aside className="band">{frontmatter.eyebrow}</aside>
      <div className="body">{children}</div>
    </div>
  );
}
export const components = { "layout:spotlight": SpotlightLayout };
```

</How>

<Notes>
Custom layouts are components the deck passes to `<Deck components>`, keyed `layout:` plus the name. They get the slide's frontmatter and options, so a layout can be driven by any key you invent — this one reads `eyebrow`. A built-in name can be replaced the same way.
</Notes>

## The default: top-aligned, padded

A heading, then the content, from the top. Any slide that names no layout gets this one — the first slide of a deck gets `cover`.

## Terms that explain themselves

<Cols cols="1.1fr 1fr" gap="2.5rem" align="start">
<Col>

Rest the pointer on a dotted word: the cursor fills like a pie, then the definition opens. **Click** pins it, <Kbd>F</Kbd> reaches it from the keyboard, <Kbd>Esc</Kbd> closes it.

Nothing on this slide was tagged. The compiler links each slide's first mention of an entry in `glossary.yaml` — MDX, a Durable Object, KaTeX.

By hand: <Term id="mdx">other words for an entry</Term>, or a <Term def="Written where it is used, with **Markdown** and $e^{i\pi} = -1$." tag="One-off">one-off definition</Term>.

</Col>
<Col>

<How>

```yaml [glossary.yaml]
Durable Object:
  def: One addressable instance of a class…
  more: A deck's room is one.
  aliases: [Durable Objects]
  tag: Cloudflare
  see: [WebSocket hibernation, D1]
D1: Cloudflare's serverless SQLite.
```

```mdx
<Term id="mdx">other words</Term>
<Term def="…">one-off definition</Term>
```

</How>

</Col>
</Cols>

<Notes>
The glossary is a YAML file beside deck.mdx. At build time the compiler finds the first mention of each entry on every slide and links it; `terms: false` in a slide's frontmatter turns that off.

`<Term>` does it by hand, for other wording or for a definition written in place. Cards are private to whoever hovers until the presenter view turns on Share terms — then they open on the projector and every phone.
</Notes>
