## One slide, any framework

<Clicks>

- A slide is HTML, so nothing about it requires React — an **island** is one piece of another framework living inside one
- A renderer knows two things: how to put a component into an element, and how to take it out
- `client="slide"` is the deck's own hydration rule: alive while you are here, gone when you leave
- The framework arrives with the slide that needs it — **none of these was in this deck's first load**
- Below: a **custom element**, **Vue**, **Svelte**, **Solid**, **Preact**, **Qwik**, **Angular**, **Fresh** — 195 bytes of **WebAssembly**, **Leptos** compiled from Rust, and **CPython** itself
- Step a click and each island is handed new props — they keep counting, because they were updated rather than rebuilt
- Svelte needed no `framework="svelte"`: a Vite plugin stamped the compiled component, because nothing else could
- Solid and React both want `.tsx` — the deck gives each plugin a glob, which is the one thing Astro gets for free and a deck does not

</Clicks>

<Notes>
Measured on this deck, not asserted. [click] The engine ships React and custom elements; every other framework is a package exporting a renderer. [click] The contract is deliberately two functions wide: put a component in an element, take it out again. [click] A deck keeps neighbouring slides mounted so transitions do not stall, so hydrating all of them is how a phone runs out of memory — an island exists only while its slide is up. [click] Registering Vue eagerly put 64 kB of its runtime in the first chunk, paid on slide one by every viewer; a renderer is registered as a name and an import instead, and each framework's chunk is fetched on arrival here. [click] Three runtimes on one slide, none of them bothering the others. [click] Press the arrow — the step changes and the counts do not restart, because each renderer was handed new props instead of being torn down. A chart would keep its animation; a half-typed form would keep what you typed. [click] And Svelte is why the engine asks the build rather than guessing: compile the same component for production and there is nothing left in it that says Svelte. A Vite plugin stamps it as it is compiled. [click] Solid is the same story one step further: its component is a plain function, exactly like React's, so nothing can tell them apart and both plugins want the same file extension. The deck hands each one a glob and they stay out of each other's way.
</Notes>
